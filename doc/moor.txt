1. INTRODUCTION                                            *moor-introduction*

moor.nvim captures notes and todos without leaving your code. Files are plain
markdown in a directory you choose — point it at a synced vault (iCloud
ZenNotes, a git repo, Obsidian) and everything is readable and editable on
your other devices too.

moor is not a knowledge-base plugin. It shares exactly one concept with
Obsidian/ZenNotes: |moor-backlinks|.

To "moor" a boat is to tie it to a fixed point. moor ties todos to code:
a captured todo can carry a `file:line` reference and jump back to it.

==============================================================================
2. REQUIREMENTS                                            *moor-requirements*

- Neovim 0.11 or newer.
- No plugin dependencies. Lists use |vim.ui.select()|, so your installed
  picker (telescope ui-select, snacks, fzf-lua, dressing, mini.pick) is used
  automatically.

3. CONFIGURATION                                          *moor-configuration*

Calling setup() is optional; these are the defaults: >lua

  require("moor").setup({
    notes_dir = "~/notes",
    ignore = { ".git", ".obsidian", "trash", "archive" },
    capture = {
      note_file = "Captures.md",  -- os.date() tokens expand
      timestamp = true,           -- "## HH:MM" heading per capture
      window = { width = 0.5, height = 0.3, border = "rounded", title = " moor " },
      maps = { promote = "<C-p>", abort = "<C-c>" },
    },
    todo = {
      dir = "todo",
      toggle_states = { " ", "x" },
    },
    dashboard = {
      window = { width = 0.7, height = 0.7, border = "rounded", title = " open todos " },
      icons = { open = "○", done = "✓" },  -- false = raw "- [ ]" brackets
      maps = { toggle = "t", jump = "<CR>", jump_context = "gd", refresh = "r", close = "q" },
    },
    links = { new_note_dir = "" },
    keymaps = {                            -- global maps, applied by setup()
      capture_note = "<leader>nn",
      capture_todo = "<leader>nt",
      capture_todo_context = "<leader>nT",
      add_todo = "<leader>na",        -- prompt, moored by default
      add_todo_plain = "<leader>nA",  -- prompt, no file:line
      dashboard = "<leader>nd",
      toggle = "<leader>nx",
      follow_link = "<leader>nf",
      backlinks = "<leader>nb",
      open_todo = "<leader>no",
    },
  })
<
`keymaps = false` defines no global maps (bind the |moor-api| yourself); a
single entry set to false skips that map; a different lhs rebinds it.

==============================================================================
4. COMMANDS                                                    *moor-commands*

:Moor capture [todo] [context]                                 *:Moor-capture*
    Open the capture float. `todo` routes lines to the project todo file;
    `context` moors the capture to the current cursor position.

:Moor todo [plain]                                                *:Moor-todo*
    One-motion todo capture via |vim.ui.input()|, moored to the cursor
    position by default. `plain` skips the file:line reference.

:Moor dashboard                                              *:Moor-dashboard*
    Open the open-todo dashboard. See |moor-dashboard|.

:Moor toggle                                                    *:Moor-toggle*
    Toggle the checkbox on the current line (any buffer).

:Moor follow                                                    *:Moor-follow*
    Follow the [[wikilink]] under the cursor, offering to create the note.

:Moor backlinks                                              *:Moor-backlinks*
    List notes linking to the current note and jump to a selection.

:Moor open                                                        *:Moor-open*
    Open the project todo view: the |moor-dashboard| scoped to this project's
    todo file. Done tasks stay visible, struck through (|hl-MoorDone|); the
    same keymaps apply. Use <CR> to open the underlying file for free editing.

==============================================================================
5. API                                                              *moor-api*

>lua
  local moor = require("moor")
  moor.setup(opts)                             -- configure
  moor.capture({ mode = "note"|"todo", context = boolean })
  moor.add_todo({ context = boolean })         -- vim.ui.input prompt;
                                               -- moored unless context = false
  moor.dashboard()
  moor.toggle_todo()
  moor.follow_link()
  moor.backlinks()
  moor.open_todo()
<
==============================================================================
6. CAPTURE                                                      *moor-capture*

The capture float is a scratch markdown buffer over your code.

  :w        save to the vault and close — the single "done" gesture
  <C-p>     promote: reopen the same buffer in a split for longer writing
            (:w there still saves to the vault)
  <C-c>     abandon without saving

Note captures append to `capture.note_file` under `notes_dir`. The file name
passes through |os.date()|, so "inbox/%Y-%m-%d.md" produces daily notes. New
files get a "# Title" first line.

Todo captures turn each non-blank line into an open task in the project todo
file. Lines that already are tasks keep their state; when capturing with
context, a hand-typed task line without a mooring gets the stashed one
appended.

==============================================================================
7. TODOS                                                          *moor-todos*

Todos are ordinary markdown checkboxes: >
  - [ ] open
  - [x] done
<
Captured todos land in `<notes_dir>/<todo.dir>/<project>.md`, where <project>
is the basename of the git root (or of the cwd outside a repo).

A todo captured with context carries a trailing code span: >
  - [ ] handle EOF case · `internal/server/conn.go:142`
<
The path is project-root-relative. On other devices it is plain readable
monospace; in nvim the dashboard's `gd` jumps to it.

==============================================================================
8. DASHBOARD                                                  *moor-dashboard*

`:Moor dashboard` scans the whole vault for open tasks and groups them by
source note. Buffer-local maps (configurable):

  <CR>    jump to the task's line in its source note
  gd      jump to the moored code location, if the task has one
  t       toggle the task in its source file; the item disappears
  r       rescan
  q       close

The active keys are pinned in the float's bottom border (omitted when
`dashboard.window.border` is "none"). |moor.toggle_todo()| (your global
toggle binding) also works inside the dashboard.

Checkbox rendering is configurable via `dashboard.icons` — for example
`{ open = "○", done = "✓" }`. Wikilinks render without their [[brackets]],
highlighted with the MoorLink group (default: |hl-Underlined|); aliased links
show the alias. Files on disk always keep plain markdown.

The dashboard has two scopes. The default aggregates every open task in the
vault (toggled tasks disappear from it). The project scope (|:Moor-open|)
shows a single project's todo file with done tasks kept visible and struck
through — toggling flips the strike on and off.

                                                                  *hl-MoorDone*
Done tasks render with the MoorDone highlight group (default: strikethrough
only). Define it yourself to restyle: >lua
  vim.api.nvim_set_hl(0, "MoorDone", { strikethrough = true, fg = "#565f89" })
<

The dashboard never caches: it rescans when opened, after every toggle, and
on |FocusGained| — so edits synced in from other devices show up. Toggling
re-reads the source line first and refuses to write if the note changed
underneath (a sync landed); it rescans instead.

==============================================================================
9. BACKLINKS                                                  *moor-backlinks*

Wikilinks resolve by note title, i.e. the file name without ".md" — the
ZenNotes/Obsidian convention. [[Title]], [[Title|alias]] and [[Title#heading]]
are all recognized, case-insensitively. Backlink listings go through
|vim.ui.select()|.

==============================================================================
10. FILE FORMAT                                              *moor-file-format*

Everything moor writes is plain markdown, compatible with ZenNotes and
Obsidian:

- No frontmatter. First line is "# Title"; the file name is "Title.md".
- Tasks are "- [ ]" / "- [x]" list items.
- Wikilinks are "[[Note Title]]".
- Code contexts are inline code spans: `path:lnum`.

moor never caches file contents, skips unreadable files (evicted iCloud
placeholders), and verifies lines before rewriting them, so external sync is
safe by construction.
